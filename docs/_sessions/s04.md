5. OK, time to add new functionality. For each of the following pieces of functionality, please add at least one test that exercises phonenix\_test’s functionality *with* and *without* the decorator. For `skipif`, please test both true and false conditions. 

   **Advice from Chelsea:** I can’t check if you write the *feature* first and *then* the tests, or *first* the tests and *then* the feature, but I *recommend* writing the tests first. **Why:** writing the test is going to give you an opportunity to get your head around what each of the decorators needs to do before you write it. You can use the text of your test to ask questions in office hours or in the Slack channel if you have them, and also, having your head around this will make each decorator easier to write. 

   **More advice from Chelsea:** You’ve got access to the @mock decorator in [manipulators.py](http://manipulations.py). I left that in there on purpose for you as an example of a decorator that takes arguments. 

   Add the following decorator functionalities to phoenix\_test (I am fine with you implementing them inside of the [manipulators.py](http://manipulators.py) file, but you’re also welcome to put them in their own separate file/s, if you prefer):

   1. **`@phoenixtest.skipif(condition, reason)`** \- If a test has this decorator, it will be skipped if a specified `condition` evaluates to `True`. It is useful for skipping tests based on environmental factors, operating system, or Python version. Check out the [documentation for @pytest.mark.skipif](https://docs.pytest.org/en/stable/how-to/skipping.html) for examples of how this should work.  
   2. **`@phoenixtest.focus`** \- Add an optional parameter to `.run()` and `.run_all()` called focus. When focus is True, *only* the tests marked with this decorator are run.  
   3. `@phoenixtest.expected_to_fail` **\-** If a test has this decorator, then it is expected to fail (for example, it tests behavior that is unfinished or buggy). If a test marked with this fails, the output of the test runner should be `test_name: fails as expected` and the number of failures reported at the end of .run() and .run\_all() should not include this test. If this test PASSES, the output of the test runner should be `test_name: unexpectedly passes.`You should also change the colors of these outputs from red and green to some other color scheme so they don’t blend into the rest of the test output, but I am happy for you to make a judgment call on what those colors should *be*. You can check out the [documentation for @pytest.mark.xfail](https://docs.pytest.org/en/stable/how-to/skipping.html) for some examples of using a decorator like this, but *pytest’s version has more features* than I am asking you to write for phoenix\_test here—you do not need to implement condition, reason, raises, run, or strict arguments for yours.
