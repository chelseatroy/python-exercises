         `4` (not 4.0)  
         `6` (not 6.0)  
         `0` (not 0.0)  
         `12` (not 12.0)  
         `5` (not 5.0)

If the result *is not* a whole number, *I do* want the decimals, out to *two significant figures*. [This Python Enhancement Proposal (we call these PEPs)](https://peps.python.org/pep-0238/) tells the story of how to do whole number division in Python 3+, and why it’s that way. [This piece of documentation](https://docs.python.org/3/library/stdtypes.html#str.format) discusses how to format numbers for display in Python.  
      5. You may import the Python io module and use that for reading and writing files ([here’s documentation on exactly how to use that](https://docs.python.org/3/library/io.html)—you also read file I/O documentation already in your homework reading). You can also import sys to grab the argument to your function. You may use the functions available to you in standard python, including the ones on the `str` class. Do not import any other modules, like `re` or `operator` or `string`—regular degular python functions and keywords only, please. Please do not use the `eval()` function, either (or anything that does what the eval function does). Finally, the python code should not reach out to any external APIs.  
      6. When we grade this assignment, we should be able to run your program on a text file *other than specifically* math\_problems.txt.

         2. Files with arithmetic phrases *like* the ones in math\_problems.txt should get solution files with the right answers to the math problems in our file.   
         3. I promise you that the math problem files we use for grading  *will only include words, characters, and general situations you see represented in math\_problems.txt.* It might be worth generating a couple of word math problem files of your own to test that your program can handle them. I’d like to see results for *all* of them.
