## \[20\] Q&A:

  1. Popping and freeing: Does popping a value from Python's evaluation stack only
     remove a reference, or can it also deallocate the underlying object, similar
     to what happens when a stack frame is popped in C?
  2. Bytecode and everyday code: Should the understanding of bytecode instructions
     and the internal stack mechanism inform how we write "regular" programs, and
     how so?
  3. 3.14's speedups: How much of a performance difference can Python 3.14's new
     bytecode optimizations make in practice? Are there situations where we would
     notice a significant difference between Python versions running the same code?
  4. Choosing a dunder: How does Python decide which dunder method to call when I
     use normal operations?
  5. `|` vs `|=`: Why does `|` create a new dictionary while `|=` updates the
     existing dictionary?
  6. Rewriting bytecode: How does the interpreter rewrite bytecode while the
     program is running?
