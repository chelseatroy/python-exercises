2. Surprise\! I’m having you write tests again. At least this time you don’t have to test a *test framework* :). Write a test for a sort function, that sorts your whole dataframe by one of the columns. Make sure you return the sorted dataframe so that sorting fits into the **fluent interface**, and update one of the tests in test\_chained\_operations to exercise this. Implement the sort function.

   **What’s a fluent interface?** It’s an API where each method returns an object you can call the next method on, so a consumer can chain several calls into one expression. phoenixcel already works this way: `from_csv`, `assign`, and `where` each return a dataframe, and `group_by` returns a GroupBy, which is what lets `test_chained_operations.py` write `DataFrame.from_csv(csv_path).assign(...).where(...).group_by(...).describe_with(...)`. If your sort returned `None` (the way `list.sort()` does), the chain would break there. If it returns the sorted dataframe, consumers can put `.sort(...)` anywhere in the chain.

3. Now, add a test and implementation for a new parameter to your sort function allowing consumers to select between sorting in ascending or descending order. 

   

4. Add a test and implementation for taking in *two* columns such that: if the values of the FIRST sort column are equal, then sort by the SECOND sort column.

5. Add a test for generalizing your solution to \#4 to work for an *arbitrary number of columns*—and then implement so that it passes.

6. Take a look at your DataFrame code. How does it look? How is it organized? Do you find it easy to read? Make any changes that you would like to make to better organize this code. Do make sure, of course, that all of your tests still pass :).

   

7. **\[ONE POINT BONUS\]:** Write a test for a join function, that allows you to append two dataframes together based on the value of a column. For example, you have df with a column called “letters” with the values \[a, b, c\] and a column called “numbers” with values \[1, 2, 3\]. You have another dataframe called other with a column *also* called “letters” with the values \[b, a, c\] and a column called “colors” with \[blue, green, purple\]. In this case df.join(other, on\_column="letters") should give a dataframe with rows like:  
   1. Letters: a, numbers: 1, colors: green  
   2. Letters: b, numbers: 2, colors: blue  
   3. Letters: c, numbers: 3, colors: purple

Do note that the order of the values in the result preserves alignment with the values in the joining column.

Then make the test pass by implementing the functionality :) 

**Decide how to handle edge cases:** values in the join column in one dataframe and not the other, only one of each value in the join column in one dataframe and multiples in the other, et cetera. For inspiration on this, I recommend reading [this illustrated primer](https://www.programiz.com/sql/join) about joins in SQL; there are several types, each designed to react differently to some of these cases. **Note that the reflection will ask you to speak to what choice you made here and why.**
