Session 6 · How Python runs your code

The Stack Machine

Before Python runs your code, it compiles it into bytecode: a list of tiny instructions like LOAD_FAST and BINARY_ADD. Then a loop in the interpreter runs those instructions one at a time. Almost every one of them does the same kind of thing: it pushes values onto a stack, or pops them off. Here's what that looks like.

Every listing below is real output from dis.dis() in Python 3.10.8. To run the examples yourself, start python3.10 and type import dis first; every example assumes you have. Newer Pythons print something different; the last section shows you what, and why.

From source code to a running loop

1 · You write

    return a + b
2 · The compiler makes

A code object: the instructions as bytes, plus a table of constants and a list of variable names.

4 · The interpreter

Runs one instruction, moves to the next, and repeats until something says RETURN_VALUE.

That interpreter is, at its heart, one enormous loop with a switch statement inside it: one case for every kind of instruction. In Python-flavored pseudocode:

# the shape of CPython's main loop (the real one is C, in Python/ceval.c)
while True:
    instruction = code[next_offset]
    next_offset += 2                      # each 3.10 instruction is 2 bytes
    match instruction.name:
        case "LOAD_FAST":   stack.push(slots[instruction.arg])
        case "BINARY_ADD":  right = stack.pop(); left = stack.pop(); stack.push(left + right)
        case "RETURN_VALUE": return stack.pop()
        ...                               # about 125 more cases

          Why is it called LOAD_FAST? Is there a LOAD_SLOW?

          What each one learned
          
      
          
        LOAD_GLOBAL→LOAD_GLOBAL_BUILTINrange was in builtins last time: if the dictionaries haven't changed, skip both lookups
        CALL→CALL_BUILTIN_CLASScalling a class written in C, like range
        FOR_ITER→FOR_ITER_RANGEonly ever saw a range iterator, so it steps it directly
        BINARY_OP→BINARY_OP_ADD_INT+= on two ints
        RESUME→RESUME_CHECKa lighter version
        JUMP_BACKWARD→JUMP_BACKWARD_NO_JITa lighter version; NO_JIT because 3.14's experimental JIT compiler is off
