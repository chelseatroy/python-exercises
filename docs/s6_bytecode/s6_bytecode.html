Session 6 · How Python runs your code

The Stack Machine

Before Python runs your code, it compiles it into bytecode: a list of tiny instructions like LOAD_SMALL_INT and BINARY_OP. Then a loop in the interpreter runs those instructions one at a time. Almost every one of them does the same kind of thing: it pushes values onto a stack, or pops them off. Here's what that looks like.

Every listing below is real output from dis.dis() in Python 3.14.3. To run the examples yourself, start python3.14 and type import dis first; every example assumes you have. Bytecode changes from one Python version to the next, so any other version will print something a little different.

4 · The interpreter

Runs one instruction, moves to the next, and repeats until something says RETURN_VALUE.

That interpreter is, at its heart, one enormous loop with a switch statement inside it: one case for every kind of instruction. In Python-flavored pseudocode:

# the shape of CPython's main loop (the real one is C, in Python/ceval.c)
while True:
    instruction = code[next_offset]
    next_offset += instruction.size        # 2 bytes, plus any cache after it
    match instruction.name:
        case "LOAD_FAST_BORROW": stack.push(slots[instruction.arg])
        case "BINARY_OP":   right = stack.pop(); left = stack.pop(); stack.push(left + right)
        case "RETURN_VALUE": return stack.pop()
        ...                               # over 200 more cases

How to read one line of dis output

The line with L1:, taken apart. Hover over or tab to a piece.

    Why are some names so long?

    LOAD_FAST_BORROW_LOAD_FAST_BORROW two instructions fused into one: one trip through the loop instead of two
    LOAD_FAST_BORROW_LOAD_FAST_BORROW 1 (a, b)= LOAD_FAST_BORROW 0 (a)+LOAD_FAST_BORROW 1 (b)

    There's only one argument byte, so each half gets 4 bits:

    100000001→slot 0 (a), slot 1 (b) 5200110100→slot 3 (result), slot 4 (item)
    _BORROW every object counts the references to it; a borrow skips the count
    LOAD_FAST1→2→1add one when it's pushed, subtract one when it's popped
    LOAD_FAST_BORROW1the count never moves: less work for the same value on the stack

    The compiler borrows only when it can prove the variable's slot will keep the object alive for as long as the stack needs it. Otherwise it uses plain LOAD_FAST.

      Your comprehension's i shares a slot with any i the function already has. So LOAD_FAST_AND_CLEAR saves the old value on the stack first (NULL here, since i was empty), and STORE_FAST 0 (i) puts it back afterward. That's why i doesn't leak out of a comprehension.

      The interpreter rewrites the bytecode while it runs
      
    
      
      
      How Python gets faster without changing your code: once an instruction has run a few times, the interpreter swaps it for a version specialized to what it saw. The cache bytes after an instruction are where it keeps notes for this.
